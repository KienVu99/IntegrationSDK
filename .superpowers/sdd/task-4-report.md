# Task 4 Report: IAdProvider, AdManager

## What was implemented

- `Core/Runtime/Ads/IAdProvider.cs` — interface with `Initialize(IntegrationSDKConfig)`,
  `ShowInterstitial(string)`, `ShowRewarded(string, Action)`, `ShowAppOpen(string)`.
- `Core/Runtime/Ads/AdManager.cs` — static forwarding facade holding a single
  registered `IAdProvider` (not fan-out). `RegisterProvider` replaces any
  previously-registered provider and logs a `Debug.LogWarning` when doing so
  (unless registering the same instance again). `HasProvider`, `Initialize`,
  `ShowInterstitial`, `ShowRewarded`, `ShowAppOpen` forward to the registered
  provider if present; otherwise log a one-time warning and no-op (no throw).
  `internal ResetForTests()` clears state for test isolation.
- `Core/Tests/Editor/AdManagerTests.cs` — 4 tests: forwarding of
  `ShowInterstitial`, `ShowRewarded` callback invocation via the provider,
  no-throw/`HasProvider == false` when nothing registered, and
  `RegisterProvider` replacing the previous provider (old provider stops
  receiving calls).

All code matches the brief verbatim, no deviations. No new asmdefs — files
live in the existing `IntegrationSDK.Core.Runtime` / `IntegrationSDK.Core.Tests.Editor`
assemblies; `InternalsVisibleTo("IntegrationSDK.Core.Tests.Editor")` from Task 1
already covers access to `AdManager.ResetForTests()`.

## Environment issue encountered and resolved

A Unity Editor GUI instance (PID 3492) was already open on this project from
a previous session, holding the project lock. The first batchmode test-run
attempt crashed with `HandleProjectAlreadyOpenInAnotherInstance`. Closed that
GUI Editor process (`CloseMainWindow`) before proceeding; no unsaved-work risk
since no scene/asset changes were pending in the GUI session (untracked-file
scan before/after showed no scene/asset diffs from it).

Also discovered that combining `-quit` with `-runTests` in the same batchmode
invocation caused Unity to exit after script compilation and asset refresh
*without* running any tests (no `-testResults` xml was produced). Removing
`-quit` (letting `-runTests` control its own quit-on-completion) fixed this —
consistent with `-runTests` batchmode instructions to omit `-quit`.
